# RoomBook

RoomBook is a meeting-room booking app: an Angular frontend, a Spring Boot REST backend and SQLite persistence.

This project was created with [GitHub Spec Kit](https://github.com/github/spec-kit) (spec-driven development). It is the companion code for the article
**[Spec-Driven Development in Practice: Building RoomBook with GitHub Spec Kit](https://dev.to/rosidotidev/spec-driven-development-in-practice-building-roombook-with-github-spec-kit-cl2)**,
where the whole workflow (constitution, specify, clarify, plan, tasks, implement) is described step by step.

## What the app does

- **Rooms**: list meeting rooms, filter by minimum capacity and equipment; an administrator can create, edit, activate and deactivate rooms (deactivation never deletes data).
- **Bookings**: see a room's day view (08:00–20:00, 15-minute steps), book a free slot, list and cancel your own bookings. Overlaps are rejected, bookings follow business rules (Monday–Friday, max 4 hours, not in the past, cancellable until 1 hour before the start).

## Project overview

### Backend (`backend/`)

Java 21, Spring Boot 3.5, plain JDBC, SQLite (file `backend/data/roombook.db`, created on first start) and Flyway migrations.

- `api/`: REST controllers, DTOs and the error handler (RFC 7807 problem details).
- `service/`: business logic and booking rules, plus the domain exceptions.
- `repository/`: JDBC data access.
- `config/`: clock, office time zone (`roombook.zone`, default `Europe/Rome`) and data directory setup.
- `src/main/resources/db/migration/`: Flyway migrations (schema and demo rooms).
- `src/test/`: contract tests that validate the API responses against the OpenAPI specification.

### Frontend (`frontend/`)

Angular 22 with Angular Material, responsive (phone, tablet, desktop).

- `src/app/rooms/`: room list, filters and the admin forms.
- `src/app/bookings/`: day availability view, booking form and "my bookings".
- `src/app/layout/`, `shared/`, `health/`: navigation shell, shared pieces and backend health check.
- `src/app/api/`: TypeScript client **generated** from the OpenAPI contract (git-ignored, regenerated by `npm start`, `npm run build` and `npm test`).
- `/api` calls are proxied to the backend on port 8080 (`proxy.conf.json`).

## Build and run

Prerequisites: JDK 21, Node.js LTS with npm, Git (Maven is not needed, the wrapper is included).

### Quick start on Windows

Open two terminals (or double-click the files):

```bat
start-backend.bat     :: http://localhost:8080
start-frontend.bat    :: http://localhost:4200
```

- `start-backend.bat` enters `backend/` and runs `mvnw.cmd spring-boot:run`.
- `start-frontend.bat` enters `frontend/`, runs `npm install` if `node_modules` is missing, then `npm start`.

Start the backend first, then open <http://localhost:4200>.

### Manual commands

```bash
# Backend
cd backend
./mvnw spring-boot:run        # Windows: mvnw.cmd spring-boot:run
./mvnw test                   # contract tests
./mvnw package                # build the jar in backend/target

# Frontend
cd frontend
npm install
npm start                     # generates the API client, then ng serve with the proxy
npm run build                 # production build in frontend/dist
npm test                      # unit tests (Vitest)
```

## The `specs/` folder

`specs/` holds the Spec Kit artifacts: one folder per feature, in the order they were built. The specs are the source of truth from which the code was generated.

| Folder | Feature |
| --- | --- |
| `001-project-setup` | Project skeleton, health endpoint and the **OpenAPI contract** (`contracts/openapi.yaml`) shared by backend and frontend |
| `002-rooms-api` | Rooms catalog REST API |
| `003-rooms-ui` | Rooms screens (browse, filter, admin management) |
| `004-bookings-api` | Bookings REST API and booking rules |
| `005-bookings-ui` | Availability day view, booking form and cancellation |

Each feature folder contains the files produced by the Spec Kit commands:

- `spec.md`: what and why, user stories, requirements and the clarifications (`/speckit-specify`, `/speckit-clarify`).
- `plan.md`, `research.md`, `data-model.md`, `quickstart.md`: technical plan, decisions, entities and validation steps (`/speckit-plan`).
- `contracts/`: API contract (the OpenAPI file in 001, notes on contract changes in the others).
- `checklists/`: requirement-quality checklists (`/speckit-checklist`).
- `tasks.md`: the ordered task list that drives the implementation (`/speckit-tasks`, `/speckit-implement`).
- UI features also include `contrast.md` (color contrast checks) and `contract-baseline.sha256` (guards against unintended API contract changes).

Other Spec Kit folders: `.specify/` (constitution in `memory/constitution.md`, templates, scripts) and `.claude/` (Claude Code skills/commands for Spec Kit).

Full setup and validation steps: [specs/001-project-setup/quickstart.md](specs/001-project-setup/quickstart.md).
API contract: [specs/001-project-setup/contracts/openapi.yaml](specs/001-project-setup/contracts/openapi.yaml).
