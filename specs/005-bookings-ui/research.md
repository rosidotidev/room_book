# Research: Booking Screens

| Topic | Decision | Rationale | Alternatives considered |
|-------|----------|-----------|-------------------------|
| Contract | Fixed. The booking contract from the bookings API is consumed through the generated client. The SHA-256 of `openapi.yaml` at the start of this feature is stored in `contract-baseline.sha256` and compared at the end (no commits exist to diff against) | Spec FR-017, backlog constraint | Editing the contract (forbidden) |
| Findings against the contract | (1) The contract has no endpoint for "my bookings by date range" or for the zone: the office time zone is a frontend constant (`Europe/Rome`, same default as the backend). (2) The availability endpoint returns confirmed bookings only, so cancelled bookings appear only in My bookings. Both are reported, not changed | Backlog: a need for a new endpoint is a finding | New endpoints |
| Routes | `/availability` (day view) and `/my-bookings`; `/` redirects to `/availability`; navigation gains "Availability" and "My bookings" next to Rooms and Admin | Plan input | Keep `/rooms` as home |
| Reused pieces | App shell, tokens, Material theme, `PageComponent`, `ProblemMessageComponent`, `IconComponent`, `RoomsFacade` (active rooms), generated `BookingsService` | Constitution X; spec FR-015 | New shell |
| Adaptive day view | One `DayViewComponent` with an input `layout`: `agenda` below 600 px, `timeline` from 600 to 1024 px, `grid` above 1024 px, chosen by `BreakpointObserver` on the same breakpoints. All three render the same vertical time axis (48 rows of 15 minutes, each at least 44 px high); agenda and timeline show one room (agenda adds a date strip; timeline a room selector), the grid shows every active room side by side | Spec FR-011..013 | Three separate components |
| Free periods | Each free 15-minute row is a button ("Free 10:15, select"); a tap starts the booking form with start = that row and end = start + 60 minutes, capped at the next occupied row and at 20:00 (selection stops at the first occupied period). Past rows of today and weekends are not selectable | Spec FR-004, FR-018 and clarifications | Drag selection (poor on touch and keyboard) |
| Booked periods | Blocks spanning their rows, showing the title (ellipsis) with the full detail (title, organizer, time) in a tooltip on hover and in the accessible name; own bookings (organizer equals the remembered name, ignoring case and spaces) get the label "Yours" and a distinct token; every state carries a text label and an icon | Spec FR-002, FR-003 | Color only |
| State tokens | Semantic aliases in `tokens.css` that point to existing palette colors (free = surface, booked = accent-soft, own = accent, cancelled = inactive-soft); no new color values | Spec FR-015, constitution X | New colors |
| Refresh | After create or cancel the day view reloads; the container fades in using `--motion-fast`, which is 0 ms under `prefers-reduced-motion` | Spec FR-008; 150 ms restrained motion | Optimistic update |
| Time conversion | `office-time.ts`: office-local date and time to an ISO string with the office offset (via `Intl` and the `Europe/Rome` zone), parts of a returned ISO string read directly (it already carries the office offset), "now in the office zone" via `Intl`; `canCancel(start, now)` is true when at least 60 minutes remain | Contract times are with offsets; the browser may be in another zone | Browser local time |
| Organizer memory | `OrganizerStore` in `localStorage` (guarded by try/catch), written when a booking is made or a name is entered; pre-fills the form and My bookings | Clarification | Cookies; server state |
| Booking form | Reactive form: room (active rooms), date, start and end selects in 15-minute steps (start 08:00-19:45, end 08:15-20:00), title, organizer. Pre-checks: title and organizer required and at most 100 characters, end after start, at most 4 hours, not in the past, not a weekend. Server rejections are shown with the shared problem message above the actions and every value is kept | Spec FR-005..007 | Free-text times |
| Form container | Phone: full-screen dialog; tablet: centered dialog (a bottom sheet is allowed, a dialog chosen); desktop: right-anchored side panel. A shared `responsiveDialogConfig` helper (also used by the rooms administration) decides | Spec FR-011..013 | Separate routes |
| My bookings | Name field (remembered), list from `listBookingsByOrganizer`; phone one-column cards, tablet two-column cards, desktop a table with a status column; status shown with label and icon; Cancel disabled with an explanation when fewer than 60 minutes remain or the booking started; cancelled bookings stay listed | Spec FR-009, FR-010 | Hiding cancelled |
| Tests | Vitest component tests: day grid rendering (rows, booked blocks, free buttons, own and empty state, layouts), selection capped at the next occupied row, form error display and data kept, My bookings cancel rules; plus an end-to-end happy path (create, see in the grid, cancel) run against the real backend with the browser tool and recorded in the quickstart | Plan input | Automated browser suite (heavy) |
| Verification | 360, 768 and 1280 px through same-origin iframes of the exact width, plus keyboard, touch-size and contrast checks | Plan input | Resizing the window (it reports a scaled viewport) |
